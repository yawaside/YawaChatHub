# Правила работы с репозиторием

Требования владельца проекта. Соблюдать при каждом изменении — без
напоминаний и без отдельного запроса.

## 1. README.md не трогать

Файл `README.md` — витрина проекта, её содержимое утверждает владелец.

- **Не изменять, не дополнять и не переоформлять `README.md`** ни при каких
  правках кода, исправлениях ошибок или добавлении возможностей.
- Единственное исключение — прямой и явный запрос владельца изменить README.
- Не добавлять в README разделы о сборке, компиляции, разработке, зависимостях
  разработчика и внутреннем устройстве: там только описание приложения для
  обычного пользователя, ссылки на скачивание, донат, телеграм-группу и
  трансляции автора.

## 2. Список изменений — только для пользователя

Файл `CHANGELOG.md` обновляется при каждом заметном изменении приложения и
пишется на языке пользователя, а не разработчика.

**Формат**

- Заголовок версии строго `## [X.Y.Z]` — из него собирается текст релиза.
- Внутри версии — смысловые разделы с заголовком `###`.
- Пункт — одна мысль в 1–2 строки: что было не так и что теперь работает.
- Новые версии добавляются сверху; старые записи не переписываются.

**Запрещено упоминать**

- имена файлов, классов, функций, методов и переменных;
- названия библиотек, пакетов, API, эндпоинтов и протоколов;
- пути в коде, номера портов, ключи реестра, фрагменты кода;
- детали сборки, CI, публикации и внутренней архитектуры.

**Правильно:** «Озвучка заработала на компьютерах, где раньше молчала».
**Неправильно:** «Добавлен резервный декодер NLayer в `EdgeTts.cs`».

## 3. Общее

- Технические подробности остаются в комментариях к коду, а не в документации
  для пользователя.
- Любые новые пользовательские ссылки (донат, соцсети, сообщество) берутся из
  раздела «Поддержи автора» в приложении и должны совпадать с ним.
